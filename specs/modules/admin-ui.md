# 模块规格：admin-ui（简单管理页）

> 版本 v1.0 · 状态 定稿（2026-11-13 冻结） · 整体优先级 **P1**（时间盒 ≈ 3 小时）；标 ★ 的项在答辩演示路径上，**必做**。

## 1. 目标

用一个**无需构建**的单页应用，让运营可以走完演示全流程：导入 → 评分 → 审核 → 创建任务 → 启动 / 暂停 / 恢复 → 查看明细与统计 → 查日志。API 才是主角，页面只是它的"遥控器"。

## 2. 范围与非目标
- **范围**：`/admin/` 静态页（`index.html` + `app.js` + `style.css`），通过 `fetch` 调用 `/api/v1/*`。
- **非目标**：框架 / 打包 / 路由库 / 国际化 / 响应式精修 / 图表库（统计用数字卡片与简单条形即可）。

## 3. 页面（标签页）

| 页 | 内容 | 关键交互 |
|---|---|---|
| ★ 概览 | 全局计数卡片（线索 / 池 / 任务 / 近 24h 发送） | 刷新 |
| ★ 线索 | 导入区（"导入 Mock 数据" 按钮、CSV/JSON 上传）；导入报告（含错误列表）；"运行筛选"按钮；线索表（状态、分数、命中原因、脱敏号码、可触达预估）；待确认队列 | 筛选、通过 / 拒绝（可填备注）、批量选择 |
| ★ 任务 | 任务列表（带汇总）；"新建任务"向导：选模板 → 选条件 → **干跑预览** → 创建；任务详情：状态徽章、统计卡片、明细表（过滤 status / reason）、**操作按钮（随状态启用）**：启动 / 暂停 / 恢复 / 取消 | 运行中每 2 秒自动刷新；熔断时显示提示 |
| ★ 合规 | 授权列表；黑名单 / 退订列表；"加入黑名单"；**"模拟收到 STOP"**（调用 `/demo/inbound-stop`，仅 DEMO_MODE 显示） | |
| 配置 | 关键词（增删改）、模板（创建 / 新版本 / 审核 / 停用 / 预览）、频控规则、设置表单 | 校验错误就地显示 |
| ★ 日志 | 审计日志与发送日志两个子页，带过滤表单 | 翻页、按任务 / 明细钻取 |

通用：顶部输入框填 `X-Admin-Token` 与操作人名，存 `sessionStorage`；401 时提示重新输入；全局错误条展示后端 `error.code` + `message` + `request_id`。

## 4. 实现约束

- 原生 JS（ES2020），单文件 `app.js` ≤ 约 800 行；不引入任何前端依赖（不用 CDN）。
- **XSS 安全**：所有来自后端的数据（尤其线索 `bio` / `display_name` 等外部文本）一律用 `textContent` / `createElement` 渲染，**禁止** `innerHTML` 拼接。
- 不在页面、控制台、`localStorage` 中出现完整号码或 token（token 仅在 `sessionStorage`）。
- 轮询只在任务详情且状态为 `RUNNING` 时启用，离开页面即停止。

## 5. 验收标准

| AC | P | 描述（给定 / 当 / 则） |
|---|---|---|
| AC-UI-001 | P1★ | 给定应用启动，当访问 `/admin/`，则返回页面与静态资源，无构建步骤、无外部网络资源 |
| AC-UI-002 | P1★ | 给定未填 token，当操作，则请求 401 并提示输入；填写后 token 仅存于 `sessionStorage` |
| AC-UI-003 | P1★ | 给定线索页，则可按状态 / 分数过滤，可见分数与命中原因，可对待确认线索通过 / 拒绝（可填备注），操作后列表更新 |
| AC-UI-004 | P1★ | 给定导入区，当点击"导入 Mock 数据"或上传文件，则显示导入报告（总数 / 导入 / 重复 / 无效 / 警告）与错误列表 |
| AC-UI-005 | P1★ | 给定新建任务向导，则可选模板与筛选条件、查看干跑预览、创建，并可跳转到任务详情 |
| AC-UI-006 | P1★ | 给定任务详情，则按钮随状态启用 / 禁用，`RUNNING` 时每 2 秒刷新统计与明细；明细可按 `status / reason_code` 过滤；`CIRCUIT_OPEN` 时显示醒目提示 |
| AC-UI-007 | P1★ | 给定合规页，则可查看授权与 suppression、加入黑名单；`DEMO_MODE` 下可"模拟收到 STOP"，之后对应明细在运行中任务里变为 `UNSUBSCRIBED` |
| AC-UI-008 | P1 | 给定配置页，则可管理关键词、模板（含审核 / 新版本 / 预览）、频控规则、设置；后端校验错误就地展示；删除最后一条必需频控规则时显示后端错误 |
| AC-UI-009 | P1★ | 给定日志页，则可按过滤条件查询审计与发送日志并分页，号码均为脱敏值 |
| AC-UI-010 | P1★ | 给定含 `<script>`、`<img onerror=…>` 的 `bio` / `display_name`，则页面以纯文本显示，不执行脚本 |
| AC-UI-011 | P1★ | 给定演示脚本的全部步骤（`docs/demo-script.md`），则每一步都能在 UI 中完成，无需 Swagger 或命令行 |

## 6. 验证方式
UI 的自动化测试成本高，原型采用：
1. **后端测试覆盖其依赖的全部 API**（已由各模块 AC 覆盖）；
2. UI 层用一份**手动验收清单**（`docs/ui-checklist.md`，T-18 产出）逐条勾选 AC-UI-001 ~ 011；
3. AC-UI-010 额外写一个轻量检查：扫描 `app.js` 不含 `innerHTML` 赋值（测试 `test_AC_UI_010_no_innerhtml_assignment`）。

## 7. 降级策略
若进度落后：只保留 ★ 项；配置页（AC-UI-008）退化为"使用 Swagger"，并在演示中说明。
