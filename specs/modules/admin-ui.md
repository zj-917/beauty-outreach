# 模块规格：admin-ui（管理页）

> 版本 v2.2 · 状态 **定稿**（2026-11-15 明确重复导入的补全语义与文案） · 整体优先级 **P1**；标 ★ 的项在答辩演示路径上，**必做**。

## 1. 目标

把管理页做成一条**可被看见的流水线**：线索库 → 智能筛选 → 人工审核 → 目标池 → 触达任务 → 审计记录。目标用户包括首次访问、没有前置知识的新手：任何一页都要能回答「我在哪一段」「现在有什么」「下一步做什么」。

页面遵循四条原则：

1. **流程即导航**：当前阶段与下一阶段始终可见，关键操作完成后就地给出下一步；
2. **先结论后明细**：计数、分布、健康度先行，表格与抽屉负责下钻；
3. **一屏一事**：每页一个主操作，其余动作渐进披露；
4. **合规可见**：授权、退订、黑名单与审计链是一等公民，而不是脚注。

演示环境使用 Mock 渠道，界面明确标注不连接真实平台；所有号码只显示脱敏值。

## 2. 范围与非目标

- **范围**：`/admin/` 静态页；`index.html` + `style.css` + `app/` 下的 ES 模块；通过 `fetch` 调用 `/api/v1/*` 与 `/demo/*`。
- **非目标**：框架、打包、路由库、图表库、外部字体 / CDN、多语言、登录 / 权限体系；不改变任何后端行为或接口。
- 真实 Instagram / WhatsApp 接入仍按项目红线保持 Mock / Stub；界面只负责如实解释现状。

## 3. 信息架构与页面结构

### 3.1 全局骨架

1. **左侧墨色导航**：驾驶舱、线索、任务、合规、记录、配置；导航项带实时计数徽标（待审核数、运行中 / 草稿任务数）；底部固定「演示向导」入口与 DB / Worker 状态。
2. **顶栏**：当前页面面包屑、快速跳转（`Ctrl/Cmd + K`）、常驻「Mock 沙箱 · 号码已脱敏」合规标识、操作人菜单（切换操作人 / 口令）。
3. **主工作区**：页头（标题 + 一句话说明 + 主操作）→ 引导条（本页要做什么 / 下一步）→ 功能卡片块。反馈就地出现在触发的卡片或抽屉内；全局 Toast 只用于成功 / 失败提示。

### 3.2 视觉与状态

- 画布为暖米色，侧栏为墨色，主色为玉石绿，铜色作点缀；状态色只表达语义：绿=成功、蓝=进行、黄=警告、红=失败、灰=跳过 / 中性。
- 颜色、图标、中文名三重表达，不依赖颜色单一通道；状态色由 `style.css` 顶部的 design token 统一定义。
- 列表默认列 ≤ 6 列，次要字段放进行内展开或详情抽屉；同一页面同时展开的一级卡片块 ≤ 3 个。

### 3.3 页面职责

| 页面 | 一句话职责 | 首屏主角 | 主操作 |
|---|---|---|---|
| ★ 驾驶舱 | 现在处于哪一步、该做什么 | 全链路漏斗 + 下一步行动 | 继续演示流程 |
| ★ 线索 | 从导入到形成目标池 | 评分分布 + 线索列表 | 导入示例线索 / 自动筛选 |
| ★ 任务 | 创建、监控、复盘触达 | 任务卡片 + 任务仪表盘 | 新建任务 / 启动 |
| ★ 合规 | 授权、名单与沙盒 | 检查链 + 三份名单 | 登记授权 / 模拟退订 |
| ★ 记录 | 审计与发送日志 | 时间线 + 过滤 | 查询 / 验证哈希链 |
| 配置 | 模板、关键词、频控、参数 | 分组配置卡 | 保存 |

### 3.4 驾驶舱

- 顶部一句话概述（今天有多少待审核、多少任务可启动）与「继续演示流程」「导入线索」。
- **全链路漏斗**：线索总数 → 已评分 → 已入池 → 最近任务目标 → 最近任务成功；每段可点击跳到对应工作区。
- **下一步行动**：按优先级给出一条主行动（导入 / 审核 / 启动 / 监控 / 查看记录），并附最近批次摘要。
- **合规健康**：授权、退订、黑名单、静默时段、发送渠道、DB / Worker 状态；一键进入合规中心。
- **最近任务 / 最近动态**：最近任务卡片与审计时间线。

### 3.5 线索工作台

页面内两个视图：

- **线索列表**：最近批次摘要 → 计数行（新导入 / 待确认 / 已入池 / 已拒绝 / 已丢弃）→ 搜索 → 类型筛选（全部 / 新导入 / 待人工确认 / 已入池 / 已拒绝 / 已丢弃，选项带数量）→ 表格 → 分页。每页条数可选 10 / 20 / 50 / 100；类型、搜索与翻页都通过后端查询完成，不受「前 100 条」限制。表格列为线索（显示名 + 用户名 + 前两条命中原因）、状态、评分、地区 / 语言、脱敏号码、操作；待人工确认行可就地填写通过 / 拒绝，其余行可打开详情抽屉。评分分布放在表格之后，基于最近 100 条线索统计。
- **用户池名单**：KPI 行（池内总数、可发送、无号码、无授权、黑名单、已退订）→ 说明「已入池 ≠ 可发送」→ 搜索 → 表格（用户名、显示名、状态、评分、地区 / 语言、可发送性、号码）→「用这批人创建任务」。
- **导入**：Mock / 文件上传 / Instagram 官方接口（Stub，未启用）；每次导入生成**批次报告抽屉**，标签页为成功 / 重复 / 无效 / 警告，默认停在第一个非零异常页，行内给中文原因；重复用户名的行不新建记录，原记录缺少的号码等资料会就地补全且状态不变，报告说明必须写清这一点；批次历史可回看任一历史报告。

### 3.6 任务与任务详情

- **任务列表**：KPI（总数 / 草稿 / 运行中 / 已完成）+ 任务卡片流（状态、进度、成功 / 失败 / 跳过迷你条、模板名）。
- **新建任务**：三步向导——① 名称与已审核模板（附正文预览）→ ② 最低分、批次与目标池摘要 → ③ 创建草稿并干跑预览（目标 / 将尝试 / 将释放 / 将跳过原因）。必须写明「预览不会发送」；创建的是草稿。
- **任务详情仪表盘**：
  - 状态横幅：中文状态 + 代码、进度环、状态说明、下一步、可用操作（启动 / 暂停 / 恢复 / 取消，不可用时解释原因）、暂停 / 熔断原因、运行中每 2 秒刷新标识；
  - 发送结果分段：目标 / 跳过 / 已发送 / 送达 / 已读 / 失败，可点击下钻；附跳过原因与失败原因分布；
  - 指标：成功率、重试次数、耗时、尝试分布；
  - 实时动态：最近 8 条发送日志，运行中自动追加；可跳到全部发送日志；
  - 明细：全部 / 成功 / 失败 / 跳过分组 + 状态 / 原因 / 搜索过滤；行内「日志」跳转发送日志；行点击打开明细抽屉；
  - 生命周期：创建、启动、暂停、恢复、完成、熔断的时间线。

### 3.7 合规、记录、配置

- **合规**：9 道发送前检查链说明 + 当前授权 / 退订 / 黑名单 / 静默时段计数；授权名单与登记；黑名单 / 退订名单（退订不可删除）；演示沙盒（模拟退订、生成回执、重置演示数据），每个动作附一句话用途与完成后下一步。
- **记录**：审计日志（操作人 / 动作 / 对象 / 编号 / 时间 / 请求编号，行展开看变更）与发送日志（任务 / 明细 / 阶段 / 结果 / 原因 / 尝试 / 耗时 / 脱敏号码）；审计页可一键验证哈希链；从任务明细「日志」可直接带参数跳入。
- **配置**：四个标签页——消息模板（按名称分组、版本、编辑草稿、审核、停用、新版本、预览渲染）、关键词（正 / 负、权重、启停、删除）、频控规则（范围、窗口、上限、启停、删除）、系统参数（按筛选 / 发送 / 消息 / 合规四组，中文名 + 释义 + 键名，按组保存，错误就地显示）。

### 3.8 演示向导

全局右侧抽屉，8 步：导入示例线索 → 自动筛选 → 审核 1 条 → 创建任务 → 查看预览 → 启动任务 → 模拟退订 → 查看统计与日志。每步显示完成 / 当前 / 待办（由真实数据判断）、一句话说明与「去操作」深链接。它是新手引导，也是答辩提词器。

## 4. 文案规范

### 4.1 基本原则

1. **全部界面文案使用简体中文**：字段名、按钮、表头、筛选项、提示语、空状态、确认弹窗一律中文；英文代码只作为辅助信息（见 4.2），不得单独作为标签出现。
2. **中文名 + 代码 + 一句话释义**：枚举值显示为「中文名（代码）」，鼠标悬停显示一句话用途；筛选下拉同样如此。空间受限的表格（如命中原因）可只显示中文名，释义放在悬停提示中。
3. **说人话**：避免"闸门""幂等""快照"等工程术语；必须使用时，紧跟一句括号解释（如"预览（不会真的发送）"）。
4. **动作与结果一致**：按钮文案描述动作（"导入示例线索"），操作后就地给出结果说明和下一步（"已导入 44 条。下一步：点击「自动筛选」"）。
5. **不泄露敏感值**：口令、完整号码、消息正文不得出现在界面任何位置；口令提示只说明"向管理员索取"。

**模板状态 / 黑名单类型 / 授权状态 / 关键词类型 / 频控范围**

| 域 | 代码 → 中文名（释义） |
|---|---|
| 模板状态 | `DRAFT` → 草稿（先审核通过才能用于任务）；`APPROVED` → 已审核（可用于新建任务）；`DISABLED` → 已停用（不再用于新任务） |
| 黑名单 / 退订类型 | `BLACKLIST` → 黑名单（运营手动加入，可删除）；`UNSUBSCRIBE` → 退订（用户主动回复，永久有效、不可删除） |
| 授权状态 | `GRANTED` → 已授权（用户同意接收）；`REVOKED` → 已撤销（用户撤回授权） |
| 关键词类型 | `POSITIVE` → 正向加分（命中后提高分数）；`NEGATIVE` → 负向减分（命中后降低分数） |
| 频控范围 | `GLOBAL` → 全局（限制整体发送速度）；`PER_RECIPIENT` → 单收件人（限制同一号码的接收频率） |
| 来源 `source` | `web_form` → 网页表单；`crm_import` → CRM 导入；`csv_import` / `IMPORT` → 文件导入；`mock` / `seed` → 示例或默认数据；`MANUAL` / `manual` → 人工登记；`INBOUND_STOP` / `inbound_stop` → 用户退订 |

**发送日志阶段与结果**

| 域 | 代码 → 中文名（释义） |
|---|---|
| 阶段 `phase` | `GATE` → 发送前检查（检查是否允许发送）；`PROVIDER` → 调用发送渠道（真正交给渠道）；`RECEIPT` → 送达回执（渠道回报结果） |
| 结果 `outcome` | `BLOCKED` → 被拦截（检查不通过）；`DEFERRED` → 推迟处理（时间条件不满足，稍后再试）；`ACCEPTED` → 已受理（渠道接受消息）；`RETRYABLE_ERROR` → 可重试错误；`PERMANENT_ERROR` → 永久错误（不再重试）；`DELIVERED` → 已送达；`READ` → 已读；`DELIVERY_FAILED` → 送达失败 |

**审计对象类型与常见动作**

| 域 | 代码 → 中文名 |

## 5. 用户流程

### 5.1 首次进入

1. 全屏进入卡：访问口令 + 操作人；说明口令不是账号密码、向管理员索取、本地演示值见 README；口令只存 `sessionStorage`。
2. 验证成功后进入驾驶舱；首屏给出「今天有多少待审核 / 任务可启动」和「继续演示流程」。
3. 任意页面 401：弹出重新输入口令的遮罩；重新验证后回到原页面。

### 5.2 10 分钟演示路径

| 时间 | 页面 | 操作 | 预期界面反馈 |
|---|---|---|---|
| 0:00 | 驾驶舱 | 讲架构与合规标识 | 漏斗、Mock 标识、合规健康 |
| 1:00 | 线索 | 导入示例线索 | 批次报告 52 / 44 / 4 / 4 / 1 |
| 2:00 | 线索 | 自动筛选 | 44 处理 / 20 入池 / 8 待确认 / 16 丢弃 |
| 2:30 | 线索 | 审核 1 条 | 卡片移入已入池，提示前往任务 |
| 3:00 | 任务 | 新建任务向导 | 预览 20 / 8 / 0 与跳过原因 |
| 3:30 | 任务详情 | 启动 → 暂停 | 状态横幅、进度环、实时动态开始滚动 |
| 4:30 | 合规 | 模拟退订 9004 | 提示回任务详情恢复 |

### 5.3 日常路径

驾驶舱看待办 → 线索导入 / 筛选 / 审核 → 用户池创建任务 → 任务详情监控 → 记录复盘。配置与合规按需调整，不占主路径。

### 5.4 异常与边界

- 空目标：创建时提示「当前筛选下没有可发送线索」，建议调整最低分 / 批次。
- 模板未审核：任务向导只列已审核模板，并在为空时给出配置页入口。
- 任务状态非法：提示状态已变化并自动刷新。
- 熔断：红色横幅说明连续失败达到阈值，可恢复或取消。
- 演示数据混乱：合规页一键重置，完成后回驾驶舱重新开始。
- 运行中刷新失败：保留当前画面，下一次轮询继续；不弹全局错误。

## 6. 实现约束

- **无构建**：原生 ES2020 模块；`index.html` 直接加载 `app/main.js`；无框架、无打包、无 CDN、无外部字体。页面按路由动态 `import()`。
- **目录**：`app/{main,api,store,router,labels,ui,charts,wizard}.js` + `app/pages/*.js`；单文件控制在约 500 行以内。
- **XSS**：所有后端文本用 `textContent` / `createElement` 渲染；禁止任何 HTML 字符串注入；图标用 `createElementNS` 构建 SVG。
- **敏感值**：口令只在 `sessionStorage`；界面、日志、错误提示不出现完整号码、token 或消息正文；号码列一律脱敏。
- **轮询**：只在任务详情且状态为 `RUNNING` 时每 2 秒刷新；离开页面、切到后台或任务进入终态立即停止；不重建整页。
- **文案集中**：所有中文名、释义、状态色集中在 `app/labels.js`；新增枚举必须同步补中文名与一句话释义。
- **令牌**：状态色、间距、圆角由 `style.css` 顶部 design token 定义，组件不得散落硬编码状态色。
- **接口**：只使用 `specs/04-api-contract.md` 中已存在的端点；不新增后端行为。已知边界：`/pool` 无搜索参数（客户端在当前加载页内过滤）；评分分布由前 100 条线索客户端聚合；`/healthz` 不含 Provider 字段，「Mock 沙箱」作为环境标识展示。
- **演示沙盒**：始终显示；服务端未开启 `DEMO_MODE` 时，点击动作会返回 404，界面就地提示未启用。

## 8. 验证方式

UI 自动化成本高，原型采用：

1. **后端测试覆盖其依赖的全部 API**（各模块 AC 已覆盖）；
2. **静态检查**（`tests/unit/` + `tests/integration/`）覆盖可自动验证的约束：
   - AC-UI-001：`/admin/` 与新模块全部 200，无外部 URL；
   - AC-UI-002 / 010：全模块无 HTML 注入 sink，token 只在 `sessionStorage`；
   - AC-UI-003：线索列表具有类型筛选、每页条数选择与后端分页参数，且不再使用多列卡片布局；
   - AC-UI-012：全部枚举中文名与释义齐全，界面无未翻译标签；
   - AC-UI-013：每个页面模块都有引导与下一步；关键提示存在；
   - AC-UI-014：任务五态均有状态说明与下一步，禁用原因字典存在；
   - AC-UI-015 ~ 017：批次标签、任务分段、用户池 KPI 的关键结构存在；
   - AC-UI-018：design token 与 tone 类齐全，无 `@import`。
3. **手动验收清单** `docs/ui-checklist.md` 逐条走查；
4. 真实浏览器按 `docs/demo-script.md` 走完整流程。

## 9. 降级策略

若时间不足：先保留驾驶舱 → 线索 → 任务 → 任务详情 → 合规 / 记录的主链路与 AC-UI-012 ~ 014 的文案与引导；演示向导（AC-UI-013 的全局路线）可退化为页面内引导；配置页可退化为 Swagger，并在演示中说明；实时动态可退化为手动刷新。批次报告的计数摘要、任务状态说明与合规名单不可降级。
