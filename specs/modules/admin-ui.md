# 模块规格：admin-ui（管理页）

> 版本 v1.2 · 状态 **定稿**（2026-11-15 人类确认；同日补充：左侧导航移除「1/2/3/4」数字编号，页内引导文案同步改为页面名称引用） · 整体优先级 **P1**（时间盒 ≈ 4 小时）；标 ★ 的项在答辩演示路径上，**必做**。

## 1. 目标

用一个**无需构建**的单页应用，让运营可以走完演示全流程：导入 → 评分 → 审核 → 创建任务 → 启动 / 暂停 / 恢复 → 查看明细与统计 → 查日志。API 才是主角，页面只是它的"遥控器"。

页面布局遵循三条原则（详见 §3）：**对象化**（批次、任务都是有生命周期的对象，以卡片为中心呈现）、**两级信息结构**（任何列表先给摘要层——计数与分布，再给可下钻的明细层）、**渐进披露**（次要字段收进展开区，首屏信息密度可控）。目标界面风格是简洁大气：留白充足、块面清晰、状态色克制且语义一致。

**目标用户还包括完全不了解本业务、首次访问、没有任何前置知识的新手。** 页面必须自解释：用户在任何一页都能回答三个问题——「我现在在做什么」「这一步怎么操作」「做完之后下一步是什么」。为此，页面全部可见文案使用简明中文，英文代码只作为辅助标识，并为每个状态、原因和设置项提供一句话释义。

## 2. 范围与非目标
- **范围**：`/admin/` 静态页（`index.html` + `app.js` + `style.css`），通过 `fetch` 调用 `/api/v1/*`。
- **非目标**：框架 / 打包 / 路由库 / 国际化 / 响应式精修 / 图表库（统计用数字卡片与简单条形即可）；不做多语言切换，不改变任何后端行为或接口。

## 3. 全局布局与设计规范

### 3.1 页面骨架（六个页面统一）

每个页面自上而下固定为四层，不得跨页混用其他结构：

1. **页头**：页面标题 + 一句话说明（保持现有 `page-head`）；
2. **引导框**：「本页要做什么」+ 操作步骤 + 「下一步」（保持现有 `guide`）；
3. **主工作区**：由若干**功能卡片块**纵向排列组成，每块只承载一个任务；块内固定为「块头（标题 + 说明）→ 摘要区 → 明细区 → 操作区」的顺序；
4. **反馈区**：操作结果就地显示在触发的卡片块内（结果行 / 提示条）；全局错误条仅用于请求级错误（401、网络错误）。

布局硬性约束：

- 同一页面同时展开的一级卡片块 ≤ 3 个，低频块默认折叠；
- **摘要层先行**：任何列表或明细上方必须有计数摘要（数字 + 状态分布），先总后分；
- **渐进披露**：表格默认列 ≤ 6 列，次要字段（简介、命中原因明细、原始键值）收进行内展开或详情抽屉；
- 卡片间距、圆角、内边距、状态色全站一致，由 `style.css` 顶部的 CSS 自定义属性（design token）统一定义，页面样式不得硬编码脱离 token 的颜色。

### 3.2 状态与颜色语义

全站统一状态色；同一状态在徽标、标签页、漏斗、表格行中使用同一颜色；颜色只表达状态语义，不做装饰：

| 语义 | 颜色 | 典型对象 |
|---|---|---|
| 成功 / 通过 | 绿 | 导入成功、已入池、已送达、已读 |
| 进行中 | 蓝 | 运行中、发送中、等待重试 |
| 警告 | 黄 | 导入警告、待人工确认、推迟处理 |
| 失败 / 禁止 | 红 | 导入无效、已丢弃、最终失败、黑名单 |
| 跳过 / 中性 | 灰 | 已跳过、无号码、新导入 |

### 3.3 导航与页面划分

左侧导航保持六页不变：`总览` → `线索` → `任务` → `合规` → `日志`，`配置` 沉底并注明"演示时通常不需要修改"。**导航项只显示页面名称，不使用数字编号**；页内引导与提示文案引用页面时同样只写页面名称（如"到左侧「任务」"）。

「线索」页内部拆分为两个**子页签**：**「导入与筛选」**（过程视图：上传、批次结果、人工审核）与**「用户池」**（资产视图：已入池可触达用户的摘要与明细）。二者心智不同——前者围绕"一次操作的结果"，后者围绕"一份人的名单"——拆分后每页信息密度可控。子页签为页内切换，不改变左侧导航结构。

### 3.4 页面内容与布局要素

| 页 | 布局结构（自上而下） | 本页引导必须包含 |
|---|---|---|
| ★ 总览 | ① 四张 KPI 卡片（大数字 + 一句话含义）；② 各模块状态摘要行（最新批次结果、运行中任务数、待确认数、近 24h 发送） | 四步演示流程一句话概览；「从第 1 步开始」入口；每张卡片的含义说明 |
| ★ 线索 · 导入与筛选 | ① 上传区（可折叠：Mock 按钮 + CSV/JSON 上传）→ ② **批次结果卡片**（见 3.5）→ ③ 批次历史列表（倒序，每行计数迷你条形图，点击展开该批次结果卡片）→ ④ 筛选结果三卡片：自动入池 / 待人工确认 / 已丢弃，各带计数徽标；审核操作只出现在「待人工确认」卡内 | 「导入 → 自动筛选 → 人工审核」三步；导入与筛选完成后分别更新「下一步」；说明只有「待人工确认」可审核 |
| ★ 线索 · 用户池 | ① 摘要 KPI 行：总用户数、状态分布、**可触达数**（有号码且已授权、不在黑名单 / 退订）、地区 / 语言分布 → ② 结构化表格：默认 5 列（用户名 / 显示名 / 状态 / 评分 / 地区），次要字段行内展开 → ③ 顶部保存视图切换：全部 / 待人工确认 / 已入池 | 说明"已入池 = 可进入发送任务"；解释可触达数的判定条件与各状态分布的含义 |
| ★ 任务 | 列表视图：新建任务块 + **任务卡片流**（每卡：名称、状态徽标、进度条、成功 / 失败摘要）；详情视图为仪表盘（见 3.6） | 「填信息 → 创建并预览 → 打开详情 → 启动」四步；预览结果逐项解释 |
| ★ 合规 | 三份名单各自独立卡片块：授权 → 黑名单 / 退订 → 演示辅助（仅 `DEMO_MODE` 显示，默认折叠） | 三份名单的区别；每个演示按钮的一句话用途；模拟退订后提示「回任务详情点恢复」 |
| 配置 | 四部分改为**折叠手风琴**，默认仅展开「关键词」；顺序：关键词 → 消息模板 → 频控规则 → 设置 | 四部分各自影响什么；模板「草稿 → 审核通过 → 可用于任务」的生命周期；修改立即生效、演示时通常不需要动 |
| ★ 日志 | 保持审计 / 发送两个子页签与过滤表单，布局不变 | 两类日志的分工；「从任务明细的『日志』按钮可直接跳到发送日志」；过滤字段的中文名与示例 |

### 3.5 批次结果卡片（导入结果的唯一展示形态）

每次导入（Mock 或文件）生成一张**批次结果卡片**；导入报告不再以纯文本块追加在按钮下方，也不再混入线索列表：

- 卡片头：来源、时间、计数摘要 `总 N · 成功 N · 重复 N · 无效 N · 警告 N`（数字按 3.2 状态色着色）；
- 卡片体为**标签页**：`✅ 成功 (N)`、`🔁 重复 (N)`、`⚠️ 无效 (N)`、`❕警告 (N)`；
- 默认停在**第一个计数非零的异常标签页**（重复 / 无效 / 警告）；全部正常时停在「成功」；
- 每个标签页内为分页表格；「重复 / 无效 / 警告」行必须显示原因的中文名与一句话释义（对应批次报告 `errors[].code`）；
- 卡片可收起为单行摘要，收起后仍显示计数摘要。

### 3.6 任务详情仪表盘

任务详情自上而下为：

1. **状态横幅**：状态徽标 + 大号进度条（已处理 / 总数）+ 操作按钮（启动 / 暂停 / 恢复 / 取消）固定在横幅右侧，随状态启用；
2. **发送漏斗**：`目标 → 跳过 → 已发送 → 送达 / 已读 → 失败` 各段显示计数；**每段可点击**，下钻到下方对应明细分组；「跳过」段可展开原因分布（黑名单 / 已退订 / 无号码 / 无授权 / 授权已撤销，数据来自统计接口的跳过原因计数）；
3. **统计卡片**：沿用现有卡片，保留一句话释义（成功率、重试次数）；
4. **明细分组标签页**：`成功 / 失败 / 跳过` 三个标签页各自分页表格，替代单一长表；行内保留「日志」按钮，状态与原因显示中文名 + 释义。

`RUNNING` 时每 2 秒刷新横幅、漏斗与当前标签页（轮询约束见 §6）。

### 3.7 通用（顶部鉴权与错误）

与 v1.1 一致：顶部输入框填访问口令（Admin Token）与操作人名，存 `sessionStorage`；401 时给出友好的中文提示并聚焦口令输入框；全局错误条展示中文说明 + 后端 `error.code` + `request_id`。

## 4. 文案规范

### 4.1 基本原则

1. **全部界面文案使用简体中文**：字段名、按钮、表头、筛选项、提示语、空状态、确认弹窗一律中文；英文代码只作为辅助信息（见 4.2），不得单独作为标签出现。
2. **中文名 + 代码 + 一句话释义**：枚举值显示为「中文名（代码）」，鼠标悬停显示一句话用途；筛选下拉同样如此。空间受限的表格（如命中原因）可只显示中文名，释义放在悬停提示中。
3. **说人话**：避免"闸门""幂等""快照"等工程术语；必须使用时，紧跟一句括号解释（如"预览（不会真的发送）"）。
4. **动作与结果一致**：按钮文案描述动作（"导入示例线索"），操作后就地给出结果说明和下一步（"已导入 44 条。下一步：点击「自动筛选」"）。
5. **不泄露敏感值**：口令、完整号码、消息正文不得出现在界面任何位置；口令提示只说明"向管理员索取"。

| 代码 | 界面中文名 | 一句话释义 |
|---|---|---|
| `KW_POS` | 正向关键词 | 简介或资料命中了正向词，加分 |
| `KW_NEG` | 负向关键词 | 命中了负向词，减分 |
| `REGION_MATCH` | 地区符合 | 地区在优先名单内，加分 |
| `REGION_MISMATCH` | 地区不符 | 地区不在优先名单内，减分 |
| `LANG_MATCH` | 语言符合 | 语言在优先名单内，加分 |
| `LANG_MISMATCH` | 语言不符 | 语言不在优先名单内，减分 |
| `BIO_TOO_SHORT` | 简介过短 | 资料太少，信息不足，减分 |
| `CLAMP` | 分数截断 | 总分超出 0–100，被截断到边界 |

**模板状态 / 黑名单类型 / 授权状态 / 关键词类型 / 频控范围**

| 域 | 代码 → 中文名（释义） |
|---|---|
| 模板状态 | `DRAFT` → 草稿（先审核通过才能用于任务）；`APPROVED` → 已审核（可用于新建任务）；`DISABLED` → 已停用（不再用于新任务） |
| 黑名单 / 退订类型 | `BLACKLIST` → 黑名单（运营手动加入，可删除）；`UNSUBSCRIBE` → 退订（用户主动回复，永久有效、不可删除） |
| 授权状态 | `GRANTED` → 已授权（用户同意接收）；`REVOKED` → 已撤销（用户撤回授权） |
| 关键词类型 | `POSITIVE` → 正向加分（命中后提高分数）；`NEGATIVE` → 负向减分（命中后降低分数） |
| 频控范围 | `GLOBAL` → 全局（限制整体发送速度）；`PER_RECIPIENT` → 单收件人（限制同一号码的接收频率） |
| 来源 `source` | `web_form` → 网页表单；`crm_import` → CRM 导入；`csv_import` / `IMPORT` → 文件导入；`mock` / `seed` → 示例或默认数据；`MANUAL` / `manual` → 人工登记；`INBOUND_STOP` / `inbound_stop` → 用户退订 |

**发送日志阶段与结果**

| 域 | 代码 → 中文名（释义） |
|---|---|
| 阶段 `phase` | `GATE` → 发送前检查（检查是否允许发送）；`PROVIDER` → 调用发送渠道（真正交给渠道）；`RECEIPT` → 送达回执（渠道回报结果） |
| 结果 `outcome` | `BLOCKED` → 被拦截（检查不通过）；`DEFERRED` → 推迟处理（时间条件不满足，稍后再试）；`ACCEPTED` → 已受理（渠道接受消息）；`RETRYABLE_ERROR` → 可重试错误；`PERMANENT_ERROR` → 永久错误（不再重试）；`DELIVERED` → 已送达；`READ` → 已读；`DELIVERY_FAILED` → 送达失败 |

**审计对象类型与常见动作**

## 5. 分步引导与状态说明

### 5.1 线索页（「导入与筛选」子页签）

1. 打开页面：引导框显示「先导入示例线索 → 再自动筛选 → 最后人工审核」，下一步提示为"点击「导入示例线索」"。
2. 导入完成后：**生成批次结果卡片**，默认停在第一个非零异常标签页；卡片头用一句话解释"总数 / 成功 / 重复 / 无效 / 警告"各计数含义；下一步提示变为"点击「自动筛选」"。
3. 筛选完成后：「筛选结果」三卡片更新计数（处理 / 自动通过 / 待确认 / 丢弃）并解释三档分数的意义；下一步提示变为"在「待人工确认」卡内逐条审核"。
4. 审核完成后：提示"审核已保存，人工决定不会被自动评分覆盖"，下一步指向「任务」；同时提示可切到「用户池」子页签查看已入池名单。

### 5.2 任务页

1. 新建任务表单：每个字段下方有一行说明（名称随意、模板只能选已审核、最低分决定哪些线索进入任务）。
2. 预览结果：必须说明"预览不会发送"，逐项解释"线索总数 / 符合条件将发送 / 已不符合条件（会跳过）"，跳过原因用中文名展示，并给出「打开任务详情」按钮。
3. 任务详情以仪表盘呈现（状态横幅 + 发送漏斗 + 明细分组标签页，见 §3.6），并按状态显示状态说明与下一步：

| 状态 | 状态说明 | 下一步指引 |
|---|---|---|
| DRAFT | 当前状态：草稿——还没有发送任何消息。 | 点「启动」开始发送；不想发送就点「取消」。 |
| RUNNING | 当前状态：运行中——系统正在逐条检查并发送，通常 20–30 秒完成。 | 等待自动刷新；如需临时停止，点「暂停」。 |
| PAUSED | 当前状态：已暂停——不会继续发送。 | 点「恢复」继续；不再发送就点「取消」。 |
| COMPLETED | 当前状态：已完成——全部线索都有了结果。 | 在下方查看明细，或点某条明细的「日志」查看过程。 |
| CANCELLED | 当前状态：已取消——任务已终止。 | 返回任务列表新建任务，或到日志页查看记录。 |

4. 按钮悬停说明：启动（开始发送）、暂停（临时停止，可恢复）、恢复（继续发送）、取消（终止任务，未发送的线索会被跳过）。
5. 按钮不可用时，状态说明必须解释原因（"只有草稿任务可以启动"等）。
6. 熔断暂停时显示醒目提示：连续失败达到阈值，系统自动暂停以避免继续出错；排查后可点「恢复」。
7. 统计卡片附一句话解释：成功率 = 成功 ÷（成功 + 失败）；重试次数 = 额外重试的总次数。
8. 明细分组标签页（成功 / 失败 / 跳过）：状态筛选与原因代码输入框使用中文标签；状态、原因均显示中文名与释义；每行「日志」按钮的悬停说明为"查看这条线索的发送过程"。

### 5.3 合规页

1. 页面引导解释三份名单：授权（谁同意接收）、黑名单（运营禁止联系）、退订（用户主动拒绝，永久有效）。
2. 授权区注明"没有记录的号码视为未授权，不能发送"。
3. 黑名单区注明"退订记录不可删除"。
4. 演示辅助区每个按钮附一句话用途；模拟退订完成后提示下一步回任务详情点「恢复」。
5. 重置演示数据前弹出确认框，说明会清空并恢复初始数据；完成后提示从「线索」重新开始。

### 5.4 配置页

1. 页面引导说明四部分的作用与"修改立即生效"。
2. 模板区说明生命周期：新建 → 草稿 → 审核通过 → 可用于任务；已审核正文不可直接改，需创建新版本。
3. 频控区说明"所有启用规则同时生效、取最严；至少保留一条全局和一条单收件人规则"。
4. 设置区每个字段显示中文名与一句话释义，代码键名作为辅助；保存后就地提示"设置已保存，立即生效"。
5. 后端校验失败时就地显示"保存失败：{中文说明}（错误码 {code}）"，且不改动其他设置。

### 5.5 日志页

1. 页面引导解释两类日志分工：审计日志 = 人对系统做了什么；发送日志 = 系统对每条线索做了什么。
2. 过滤字段全部使用中文标签并给填写示例；阶段与结果下拉项显示中文名（代码）。
3. 说明入口：任务详情 → 明细行「日志」会自动跳到发送日志并填好任务编号与明细编号。
4. 表格中号码一律为脱敏值，页面注明"号码已脱敏"。

## 6. 实现约束

- 原生 JS（ES2020），允许按页面 / 职责**拆分为多个静态 JS 文件**（`<script>` 直接引用，仍无构建、无打包、无外部依赖、不用 CDN）；文案与释义字典集中在一个独立文件；单文件 ≤ 约 800 行。
- `style.css` 顶部以 CSS 自定义属性定义 design token（状态色、间距、圆角、卡片样式）；页面样式不得硬编码脱离 token 的颜色。
- **XSS 安全**：所有来自后端的数据（尤其线索 `bio` / `display_name` 等外部文本）一律用 `textContent` / `createElement` 渲染，**禁止** `innerHTML` 拼接。
- 不在页面、控制台、`localStorage` 中出现完整号码或 token（token 仅在 `sessionStorage`）。
- 轮询只在任务详情且状态为 `RUNNING` 时启用，离开页面即停止；每次轮询只更新状态横幅、漏斗与当前激活的明细分组标签页，不重建整页。
- 文案与释义集中维护（以字典/表驱动），不得在渲染逻辑中散落魔法字符串；新增状态或原因码时必须同步补充中文名与释义。

## 8. 验证方式
UI 的自动化测试成本高，原型采用：
1. **后端测试覆盖其依赖的全部 API**（已由各模块 AC 覆盖）；
2. UI 层用一份**手动验收清单**（`docs/ui-checklist.md`，T-18 产出并随本修订补充 AC-UI-012~018）逐条勾选；
3. 静态检查（`tests/unit/`）覆盖可自动验证的文案与引导约束：
   - AC-UI-012：全部枚举中文名与释义字典齐全、界面无未翻译的英文标签；
   - AC-UI-013：六个页面均存在引导区块，关键操作后提示「下一步」；
   - AC-UI-014：任务五种状态均有状态说明与下一步指引；
   - AC-UI-010：扫描 `app.js` 不含 `innerHTML` 赋值；
   - AC-UI-018：`style.css` 顶部存在 design token 变量定义（状态色、间距），源码中无脱离 token 的硬编码状态色。

## 9. 降级策略
若进度落后：只保留 ★ 项；配置页（AC-UI-008）退化为"使用 Swagger"，并在演示中说明；任务发送漏斗（AC-UI-016）可降级为统计卡片 + 跳过原因计数表；批次结果标签页（AC-UI-015）可降级为按原因分组的分组表格；用户池摘要行（AC-UI-017）与全站布局一致性检查（AC-UI-018）可降级。但 AC-UI-012~014 的文案与引导属于演示路径，不降级；批次结果的计数摘要（成功 / 重复 / 无效 / 警告）无论如何不降级。
