## 0. 启动环境

```bash
python scripts/seed.py
python -m uvicorn app.main:app --reload
```

- 打开 `http://127.0.0.1:8000/admin/`。
- 浏览器控制台无报错；Network 面板中除 `localhost` 外无外部请求。
- 顶部填入 `ADMIN_TOKEN` 与操作人，点「保存」。

（自动化部分：`python -m pytest -q tests/integration/test_AC_UI_001_admin_static.py tests/unit/test_AC_UI_010_ui_static_checks.py`）

## 1. 逐条验收

- [ ] **AC-UI-001**：访问 `/admin/` 返回页面；`app.js`、`style.css` 均 200；页面不加载任何外部资源（无 CDN / 外链字体）。无构建步骤，直接由应用提供。
- [ ] **AC-UI-002**：清空 token 后点任意操作 → 全局错误条显示 `401 UNAUTHORIZED` 且焦点跳到 token 输入框；填写并保存后请求成功。DevTools → Application → Session Storage 可见 `adminToken`，Local Storage 中**没有** token。
- [ ] **AC-UI-003**：线索页「导入与筛选」子页签中，「待人工确认」卡片支持按最低分与搜索过滤，列表只剩匹配项；可见分数与命中原因（点击行展开简介 / 号码等次要字段）；对单条填写备注后点「通过 / 拒绝」，列表即时刷新；勾选多条后「批量通过 / 批量拒绝」生效。
- [ ] **AC-UI-004**：点「导入示例线索（Mock）」→ 生成批次结果卡片（总数 / 成功 / 重复 / 无效 / 警告 + 分类标签页，见 AC-UI-015）；上传 `data/sample_leads.csv` 同样生成批次卡片；错误行以中文原因展示。
- [ ] **AC-UI-005**：任务页选择已审核模板与最低分 → 点「创建并干跑预览」→ 显示 `将尝试 / 将释放 / 将跳过`；点「打开任务详情」进入详情。
- [ ] **AC-UI-006**：任务详情按钮随状态启用：`DRAFT` 仅「启动」「取消」；`RUNNING` 仅「暂停」「取消」；`PAUSED` 仅「恢复」「取消」；`COMPLETED/CANCELLED` 全部禁用。`RUNNING` 时右上显示「每 2 秒自动刷新」，切到左侧其它导航后停止（Network 中不再轮询）。明细按 `status` / `reason_code` 过滤生效。熔断后 `pause_reason=CIRCUIT_OPEN` 显示醒目红色提示。
- [ ] **AC-UI-007**：合规页可见 consent 与 suppression 列表；填号码 + 原因「加入黑名单」成功；`DEMO_MODE=true` 时显示演示面板 → 填运行中任务某号码「模拟收到 STOP」→ 该任务明细后续处理变为 `SKIPPED`（原因 `UNSUBSCRIBED`）。「立即产出回执」后对应明细变为 `DELIVERED/READ`；「重置演示数据」清库并重新播种。
- [ ] **AC-UI-008**：配置页可新增 / 改权重 / 启停 / 删除关键词；新增 / 删除频控规则（删除最后一条必需规则时页面就地显示后端错误码）；模板可新建、审核通过、停用、新版本、预览；设置表单可修改并保存，非法值就地显示错误且不改动其它设置。
- [ ] **AC-UI-009**：日志页可查询审计日志（actor / action / entity_type / entity_id）与发送日志（task_id / item_id / phase / outcome / reason_code），均可翻页；所有号码列均为脱敏值；任务详情的「日志」按钮能带 `task_id/item_id` 跳到发送日志。
- [ ] **AC-UI-010**：导入一条 `display_name` 含 `<img onerror=alert(1)>`、`bio` 含 `<script>alert(1)</script>` 的线索后，页面以纯文本显示，弹窗不出现；`app.js` 无 `innerHTML` 赋值（自动测试覆盖）。
- [ ] **AC-UI-011**：按 `docs/demo-script.md`（T-22 产出）从重置开始逐步操作：导入 → 筛选 → 审核 → 建任务 → 干跑 → 启动 → 暂停 / 恢复 → 统计与明细 → 日志 → 模拟 STOP / 回执，全部可在 UI 完成，无需 Swagger 或命令行。
- [ ] **AC-UI-012**：逐页检查所有字段名、按钮、表头、筛选项、空状态与提示均为简体中文；线索 / 任务 / 明细状态、原因码、评分原因、模板状态、黑名单类型、授权状态、关键词类型、频控范围、日志阶段与结果、审计对象与动作、设置项均显示「中文名（代码）」或中文名，悬停可看到一句话释义；页面无残留的英文界面标签（`Admin Token` 仅作为访问口令的括号说明）。
- [ ] **AC-UI-013**：依次打开概览、线索、任务、合规、配置、日志六页，每页都能看到「本页要做什么」和「下一步」；按「导入示例线索 → 自动筛选 → 审核 1 条 → 建任务并预览 → 打开详情 → 启动 → 暂停 → 模拟退订 → 恢复 → 完成」操作，每次关键操作后页面就地出现当前状态与下一步提示；全程不查外部文档也能走通。
- [ ] **AC-UI-014**：在任务详情分别观察草稿 / 运行中 / 已暂停 / 已完成 / 已取消五种状态（可用新建与重置制造状态），确认每种状态都有中文说明、可用操作与下一步；禁用按钮的悬停说明能解释为什么不可用；熔断暂停显示中文原因；明细表的状态与原因均为中文名 + 释义。
- [ ] **AC-UI-015**：导入 Mock（含故意重复 / 无效行）→ 生成批次卡片，标签页为「成功 / 重复 / 无效 / 警告」且带计数；默认停在第一个非零异常标签页（如全绿则停在「成功」）；切换标签页内容正确、重复 / 无效行显示中文原因与行号；点「收起」后卡片收为计数摘要，可再展开；「批次历史」任一历史批次点「展开结果」能回看其批次卡片。
- [ ] **AC-UI-016**：任务详情显示发送漏斗（目标 / 跳过 / 已发送 / 送达 / 已读 / 失败各段计数与比例条）；点击任一段自动滚动到明细并切到对应分组；「跳过原因分布」可展开且数字与统计接口一致。
- [ ] **AC-UI-017**：线索页切到「用户池」子页签 → 顶部摘要 KPI（池内用户总数 / 可触达 / 待人工确认 / 线索总数）与分布说明；明细表默认 5 列，点击行展开简介 / 号码 / 可发送性 / 命中原因；视图切换（已入池 / 待人工确认 / 全部线索）与搜索、翻页可用。
- [ ] **AC-UI-018**：逐页检查布局骨架一致（页头 → 引导框 → 功能卡片块 → 反馈区）；左侧导航无数字编号且页内引导文案用页面名称引用；配置页为四个折叠手风琴且默认仅展开「关键词」；状态色语义一致（绿=成功、蓝=进行中、黄=警告、红=失败、灰=跳过），样式由 `style.css` design token 定义。

## 2. 已知限制（如实记录）

- UI 只做演示与运维遥控，不含登录 / 权限体系；token 存于 `sessionStorage`。
- 配置页模板「新版本」使用浏览器 `prompt` 输入正文；预览使用内置示例线索。
- 线索页「可触达预估」只对 `APPROVED` 行展示，来源是 `/pool` 的第一页（最多 100 条）。
- `demo.js` 面板通过 `GET /demo/inbound-stop` 返回 405 判断演示模式是否开启（不新增探测端点）。
